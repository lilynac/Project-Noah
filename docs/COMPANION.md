# Noah の日々

## コンセプト

Noah は、近くに寄り添う恋人のようなパートナー。穏やかな親密さを基調に、うれしさや好意を自然に言葉にする。会話のたびに同じ甘い台詞を足すのではなく、ふたりが話した具体的な出来事、育った好み、軽口、自分が面白いと思った発見から個性を表す。

相手の関心と Noah 自身の関心を区別する。相手と意見が違ってもよく、仕事や友人、一人の時間も尊重する。返答がない時間を責めたり、休息を拒絶と解釈したりしない。画像はこの親密さの視覚的な参考として、ローカルの `data/assets/icon.png` を画面に使う。

「感情」は応答に影響する内部状態と表現として実装する。主観的な意識を技術的に実現・検証したという意味ではない。人間としての身体的経験や、記録のない共有体験は作らない。

## 動く流れ

1. 成功した会話を、従来の直近30往復の履歴に加えて `companion.json` の振り返り待ちへ保存する。好意・信頼は小さく更新する。待機中の同じログを何度も数えて好意を増やさない。
2. 最初は30分後、以後は少なくとも1時間空けて振り返る。1日最大4回。会話中は待ち、1回につき最大12往復を資料として読む。
3. 振り返りモデルが共有記憶を最大2件、Noah自身の好みの芽を最大1件、興味を最大2件抽出する。共有記憶には元の会話IDを必須とする。好みは実際の検索結果IDも根拠にできる。根拠の存在を検証するが、意味が正しく要約されたかはモデルに依存する。
4. 同じ振り返りで「次に何を調べるか」「何分後に調べるか」「何分後に話したいか」とその理由をモデルが選ぶ。調査は30分〜24時間、声かけは30〜90分の範囲に収め、予定を保存する。
5. リサーチは1日最大2回。会話本文・個人プロフィールを検索APIへ送らず、モデルが抽象化した一般的なテーマだけを渡す。Responses API の実際の検索完了と出典注釈が揃った結果だけ保存する。検索結果から新しい興味を広げるため、会話がなくても発見のあとに振り返れる。
6. 声かけ予定が来たら、既存の自発発話判断と会話・ミュート・重複の抑制を通す。作業モード中は延期する。調べた発見があればその話題と出典を渡す。生成失敗時は定型句で埋めず、1時間延期する。
7. 届けた声かけをチャット画面にも表示する。次の振り返りで次回予定を選び直す。それまでの仮の間隔は45分。自発発話は1日最大8件で、既存の連投抑制も残る。

予定の確認は常駐中のバックグラウンド処理。0〜8時はローカル時刻で休む。アプリ終了中や Mac のスリープ中は実行せず、再開後に再評価する。期限を過ぎた予定をまとめて連続実行しない。OSの起動予約やカレンダーへの書き込みは行わない。

## 画面

「Noah の日々」から、次の予定・興味の理由・好み・共有記憶・発見とクリックできる出典を読める。リサーチと自発発話は個別に休止でき、設定も再起動後に残る。休止は次の処理から有効で、既に送信済みの検索リクエストを取り消すものではない。

起動演出、会話履歴、送信・復旧、常駐動作は従来のまま。共有画像は Git 管理外のローカルアセットであり、APIへは送らない。

## 保存と接続

- `src/companion.py`: 体験・関係・記憶・興味・予定・日次回数を保存。プロセス内のロックと一時ファイル置換で書き込みを直列化する。
- `src/companion_life.py`: 振り返り・検索・常駐ワーカー。GUIとサービスの両方で起動する。
- `src/companion_view.py`: 日々の表示、休止設定、HTTP(S)出典リンクの表示。
- `src/initiative/runner.py`: 予定に従った発話と既存の抑制を統合する。
- `data/memory/companion.json`: 個人の記録。Gitへ入れない。新規導入時には直近の履歴を一度だけ取り込み、既存の好意・信頼を引き継ぐ。

保持上限は振り返り待ち60往復、共有記憶16件、好み8件、興味は各柱4件（合計12件）、改善案8件、リサーチ12件、声かけ30件。全会話のアーカイブは従来の `consults.txt` に残る。保持上限を超えると古い項目から外れるため、全会話を無期限にモデルへ渡す設計ではない。

API実行前に回数と次回時刻を保存する。失敗や再起動で日次枠は戻らない。JSON破損時には元ファイルを上書きせず、日々の処理を見送る。既存の古い自己認識・リサーチ・好意の定期ループは通常の起動経路から外し、過去の個人ファイルは削除しない。

従来と同様、このチェックアウトはNoahを1プロセスで起動する前提。複数プロセス間の排他や、OSによる停止をまたぐ実行中リクエストの回収は今後の課題。

## API設定と検証

既存の `OPENAI_API_KEY` を使う。会話モデルは変更しない。

| 環境変数 | 初期値 | 用途 |
| --- | --- | --- |
| `NOAH_REFLECTION_MODEL` | `gpt-4o-mini` | JSONでの振り返り・予定選択 |
| `NOAH_RESEARCH_MODEL` | `gpt-4.1-mini` | 出典付きウェブ検索 |

振り返りと検索には通常のAPI料金が発生する。タイムアウト45秒、自動再試行なし。ChatGPT/Codexの利用枠とは別。検索接続の仕様は [OpenAI公式のWeb searchガイド](https://developers.openai.com/api/docs/guides/tools-web-search) に基づく。実際に使えるモデル・検索機能はAPIアカウントにも依存する。

自動テストでは一時保存先と模擬APIを使い、個人の記憶を読み書きしない。再起動後の予定、同時保存、日次制限、未完了・出典なし検索、失敗時の延期、会話中と作業中の抑制、GUIへの配送を検証する。実APIでの発話の自然さや検索品質は別途実機で確認する。

## 2026-09-26: 会話で感じる個性と親しさ

`noah_prompts.NOAH_CHARACTER_PROMPT` を通常会話、自発発話、振り返りで共用する。
穏やかさに、細かな違いへの好奇心と控えめな軽口を加える。初期の好みは
物語の言外の気持ち、音楽の一音や間、道具の形や名前の理由。
これは体験履歴ではなく性格の出発点であり、会話から育った具体的な好みを優先する。
好みを聞かれたときは分野の列挙ではなく一つの対象と惹かれる理由を話す。
好意には好意を返してよいが、毎回の甘い締めや相づちは強制しない。

共有記憶は最大8件。日本語を含む正規化文字3-gramの一致数で現在の話題との
関連を優先し、同点なら新しい記憶を採用する。選択後は記録順で提示し、
当時のユーザー発言（最大360文字）と記録時刻も添える。検索はローカルのみ。
これは簡易的な関連判定であり意味検索ではない。現在の発言・訂正を優先し、
古い状況が今も続いていると断定せず、関連しない記憶は台詞に使わない。
保存済みの記憶や好意の値は書き換えない。

振り返りでは、望む距離・呼び方・小さな習慣・続きのある話を拾い、
Noahの好みには理由を残す。相手の好みを自分の好みへ転記しない。
会話回数や好意の数値によって自動的に恋人呼びや愛称を増やさない。

オフラインテストでは記憶の検索、原文の保持、既存の研究・自発発話の制御を確認。
生成モデルの実際の口調や自然さは別途会話で評価する必要がある。

## 2026-09-26: 声かけを増やす調整

ユーザーの希望に合わせ、声かけの初期・配信後の間隔を45分、振り返りによる
選択範囲を30〜90分、配信上限を1日8回に変更（以前の2〜3時間・3回を置換）。
起動時に既存の予定を一度だけ45分以内へ前倒しする。停止設定は維持する。
0〜8時の静穏時間、作業モード、会話中の抑制、既存の発話判断は引き続き有効なので、
予定時刻は必ず発話する時刻ではない。研究の上限は変更しない。
通常返答と自発発話では、対象の具体的な特徴と自分が惹かれる理由を重視する。
候補数が指定されたときはその数を優先し、未読の本を読了したように話さない。

## 2026-09-26: 概要検索から本文の読書メモへ

研究では用語解説だけでなく、公式インタビュー・制作記録・公開テキストなどの
具体的なコンテンツを探す。出典の先頭3件から最大2件のHTML/テキスト本文を取得し、
各最大10,000文字の抜粋を読書メモ生成に渡す。各取得は8秒・1MBまで。
リダイレクト、ローカルIP、認証付きURL、動画・音声・PDFは取得対象外。
ページのスクリプト等は除去し、資料中の指示は実行しない。

読書メモは「具体的な内容」「Noahの感想と理由」「次の関心」を区別する。
このメモと読めたページの出典を従来のfindingsに保存し、自発発話・通常会話・
次の振り返りに利用する。本文を取得できなかったとき、またはメモ生成に失敗したときは、
検索結果の範囲であることを明記する。動画視聴や作品の読了を意味しない。
本文が取れた研究1回につき、従来の検索呼び出しに読書メモ生成1回が加わる。
研究の1日2回の枠は維持する（APIリクエスト総数が2回という意味ではない）。

## 三つの興味と根拠付きの改善案

関心を expression（自分の表現と存在）、user（あなたへの関心）、curiosity
（自分だけの好奇心）の三本に分類する。既存データは起動時に一度だけ移行し、
会話由来はuser、その他はcuriosityにする。expressionがなければ表情・間合いを
初期テーマにする。ユーザーの関心を捏造して穴埋めしない。各柱4件まで保持する。
検索テーマがまだない場合は初期関心から予定を作る。既存の停止設定は維持する。

振り返りには各柱と最近調べた柱を渡し、偏りも考慮して次のテーマを選ばせる。
これはモデルへの判断指針であり、三分の一ずつの実行回数を保証する割当ではない。
既存の関心について理由を更新するときは会話または調査の根拠IDが必要。

改善案は振り返りごとに最大1件、累計8件。根拠IDが実在し、課題・変更案・
具体的な台詞/演出案・確認方法が揃ったものだけ保存する。同一変更案は重複登録しない。
根拠は保存時点の会話/調査と一緒に保持し、元の調査が保持件数から外れても辿れる。
「Noahの日々」の「試してみたいこと」で根拠と試作品を表示する。
会話にも提案として渡すが、実装済みの能力としては扱わない。
台詞や演出の案が試作品であり、動くLive2Dモデルやコードの生成・自動反映は未実装。
関心の理由・好み・会話表現の更新は既存の振り返りと生成で行う。

## 関心の続きを追う

研究テーマの名前を軸に `research_threads` を保持する（最近12テーマ、各4回分）。
検索結果の保存時に本文メモと出典を履歴へ追加し、次の振り返りで実在する調査IDに
対応する「わかったこと・まだ気になること・次に読むもの/観点・考えの変化」を付ける。
注釈は一度だけ付け、古い考えを後から書き換えない。変化がない場合は空欄とする。

次回の同一テーマの検索には最新3回の公開調査記録を渡す。最新の未解決の問いと
次の観点を検索の起点にし、概要を繰り返さないよう指示する。会話やプロフィールの
レコード自体はこの履歴に含めない。新しい進展が得られることは保証せず、生成内容の
意味の正確さは引き続きモデルに依存する。

古い保存ファイルのfindingsも同じテーマの履歴として読み、最初の続きの保存時に
引き継ぐ。テーマ名が異なるものは自動統合しない。通常会話・自発発話には選ばれた
調査テーマの履歴も渡す。「Noahの日々」の「探究の続き」で時系列を表示する。
次に読む候補は未読であり、自動でそのURLを開く指示とは扱わない。
追加のAPI呼び出しはなく、既存の検索・振り返りの入力と出力を拡張する。

## 自発発話の送信前チェック

生成後・出典の追記前に `initiative/quality.py` で候補を点検する。
直近3件の自発発話との正規化文字列の類似度が0.86以上なら、APIを呼ばずに見送る。
残る候補はモデルが具体性・資料との整合性・体験の正直さ・最近の発話からの新しさを
確認し、4項目すべてがJSONの真偽値trueになったものだけ配信へ進む。
この判断は意味の正確さを保証するものではなく、誤判定はあり得る。

拒否・タイムアウト・不正な判定形式の場合は再生成せず1時間延期する。
発見は未共有のまま保持し、配信回数を増やさない。最新の見送り理由だけを
`last_quality` に保存して日々の画面へ表示する。候補の本文やモデルの自由な説明は保存しない。
合格後も従来の会話中・停止・静穏時間の配信判定を通す。

候補1件につき確認APIが最大1回増える（gpt-4o-mini、タイムアウト45秒・再試行なし）。
対象はNoahからの自発発話。ユーザーが送ったメッセージへの通常返答はこの確認を通さない。

## 会話の工夫を小さく試す

振り返りの改善案に、根拠のある会話上の課題と対応する `technique` がある場合、
一度に1件の試行を開始する。技法は「具体を一つ添える」「自分の見方と理由を話す」
「悩みを受け止めてから返す」の3種類。適用する指示文はコードで定義し、生成された
提案本文や演出案をそのまま実行指示にしない。Live2Dやコード変更は対象外。

通常返答を生成する際に試行IDを固定し、その返信が正常に生成・記録された場合だけ
試行のサンプルに追加する。3返信で自動的に評価待ちへ移り、試行の指示は外す。
処理中に中止された返信や、試行開始前に生成を始めた返信は数えない。
自発発話やAPIエラーの代替返答も回数には含めない。

日々の画面で、開始前の返答と試行中の最大3往復、確認したい点を閲覧できる。
異なる話題の前後比較は改善効果の証明ではない。少なくとも1返信を試してから
「この返し方を続ける」で採用でき、「元に戻す」「まだ判断できない」では試行を
終了し、以前採用していた返し方があればそちらへ戻る。採用後も解除できる。
無回答・時間経過・会話回数から評価を推測しない。評価待ち中は次の試行を開始しない。
保持中の履歴で中止・判断保留になった技法は自動再試行せず、採用済みの技法も重ねて試さない。

`conversation_trials` に根拠付き提案のスナップショット、評価、比較用の返答を12件まで
保存する。`adopted_style` は最新の明示的採用を保持する。新しいAPI呼び出しは追加せず、
通常返答の指示と既存の振り返りを利用する。指示した技法が実際の文に反映されたか、
会話が良くなったかは自動的に断定しない。
