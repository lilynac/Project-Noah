# Noah のキャラクター表示

起動時は1020×760のウィンドウで、左側に大きなNoah、右側に会話を表示する。
幅800未満では上部にキャラクターを移し、画像の顔付近を中心に切り取って表示する。
元画像 `data/assets/icon.png` は変更せず、描画時に拡縮・位置合わせを行う。

`src/character_view.py` はQtの標準描画だけで、呼吸のような拡縮、緩い揺れ、画像上のポインターへの小さな追従、返信時の軽いうなずきを表現する。待機・起動・考え中・返信・エラーの表示を会話画面と同期する。

「動き ON / OFF」で静止表示に切り替えられる。設定は現在のアプリ実行中に保持する。閉じて非表示にした時や最小化した時には連続描画を停止し、再表示時に再開する。追加の画像生成・API通信・Webエンジン・OpenGL依存はない。

## Live2D との違い

現在は一枚の画像全体を動かす方式。目・口・髪を独立した部品として動かすモデルではなく、瞬き・口パク・音声同期は未実装。

本格的なLive2Dを導入するには、元絵をパーツ分けしてCubismでモデル化し、`.moc3`、`.model3.json`、テクスチャなどの組み込み用データを用意する。そのモデルを読み込むSDK連携が別途必要になる。[Live2D公式：組み込み用データ](https://docs.live2d.com/cubism-editor-manual/export-moc3-motion3-files/)

会話側は `CharacterView.set_state()` に状態を渡す構造なので、将来のモデル表示にも同じ状態通知を使える。ただし、現時点でLive2Dモデルを置くだけで読み込める機能はない。
